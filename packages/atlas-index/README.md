# Atlas index

A folder of markdown notes goes in. Generated folder indexes, a root map, and a health list come out. The library does not read or write files, and it does not use the network. The command reads one folder and, only with `--write`, updates indexes and the map.

Node 22 or later. No dependencies.

```sh
cd packages/atlas-index
npm test
```

## Command

From the repo root:

```sh
node packages/atlas-index/src/atlas.mjs --dir <folder>
node packages/atlas-index/src/atlas.mjs --dir <folder> --json
node packages/atlas-index/src/atlas.mjs --dir <folder> --write
```

Without `--write` it changes nothing. `--json` prints the result. Otherwise it prints a short summary. A refusal prints one plain message and no result. The exit code is 1 for a refusal and 0 for a result.

`buildAtlas(notes, options?)` is the same rebuild as a function. It returns the object, prints nothing, and never calls `process.exit`.

## Input

`notes` is a list of `{ path, text }`. `path` is relative, uses `/`, and ends in `.md`. `options` may be omitted.

| Option | Default | Meaning |
| --- | --- | --- |
| `indexName` | `INDEX.md` | The generated index in a folder |
| `rootMapName` | `MAP.md` | The root map |
| `indexThreshold` | `5` | A folder gets an index when it holds more notes than this |
| `maxLines` | `400` | A note longer than this is too long |

The command always uses the defaults. It reads every `.md` file under `--dir`, skipping hidden folders and symbolic links.

## Rules

**What a note is about.** Front matter is a `---` block at the top. Its `description:` wins when it has text. Otherwise the first `# ` heading wins, then the first non-empty line, then the file name. The first-line fallback is cut to 120 characters on a word boundary.

**Folder indexes.** A folder with more than `indexThreshold` notes, not counting its own index, gets an `INDEX.md`. The file starts with `<!-- Generated by atlas-index. Do not edit by hand. -->`, then the folder name as a heading, then one link per note, sorted by path: `- [About text](relative/link.md)`. Subfolders come after the notes. A subfolder with an index links to that index. A subfolder without one links to its notes. Only notes directly in the folder count toward the threshold.

**Root map.** `MAP.md` keeps the bytes above `<!-- atlas-index:start -->` and replaces everything after the marker. A map with no marker gets one appended. The generated part is one line per root note, then one line per top-level folder. A folder with an index links to that index. A folder without one links to the folder (`garden/`). A folder index still lists a subfolder's notes when that subfolder has no index.

**Hand-made indexes.** An `INDEX.md` that does not start with the generated header is a conflict. It is not written and it is not removed. A generated index in a folder that is now at or under the threshold is removed.

**Health.** Each entry is `{ kind, path, detail }`, sorted by kind, then path, then detail.

- `broken-link`: a relative markdown link or a `[[name]]` wiki link that does not match a note. `https:` and `mailto:` links are ignored.
- `orphan`: a note no other note links to. The map and generated indexes do not count, and neither do links from a note to itself.
- `duplicate`: notes whose text matches, or whose about lines match. Each group is listed once, with every path.
- `too-long`: a note over `maxLines`, or the map over 200 lines.
- `conflict`: a hand-made index.

The check does not fix notes. `writes` contains only indexes and the map. `removes` contains only generated indexes.

## Output

```json
{
  "writes": [{ "path": "garden/INDEX.md", "text": "..." }],
  "removes": [],
  "unchanged": [],
  "conflicts": [{ "path": "garden/INDEX.md", "detail": "..." }],
  "health": [{ "kind": "orphan", "path": "pantry.md", "detail": "..." }],
  "counts": {
    "notes": 1,
    "folders": 1,
    "indexesWritten": 1,
    "indexesRemoved": 0,
    "mapWritten": 1,
    "broken-link": 0,
    "conflict": 0,
    "duplicate": 0,
    "orphan": 1,
    "too-long": 0
  }
}
```

Lists are in a fixed order. The same notes produce byte-identical JSON. `counts.notes` does not include the map or index files. `indexesWritten` and `indexesRemoved` do not include the map. `mapWritten` is 1 when the map is in `writes`.

## Writes

With `--write`, each file in `writes` is written inside `--dir` by a temporary file in the same folder and a rename. A new file is mode `0600`. Replacing one keeps the mode it already has. Just before the rename, the command reads the target again. If it appeared, disappeared, or its bytes changed since the scan, that file stays as it is and is reported under `conflicts` (and leaves `writes`). A removal is skipped, and reported, if the bytes changed or the file no longer starts with the generated header. Notes are never edited or deleted. A `--dir` that contains `.git`, or that is this repository's root, is refused.

## Edge cases

Each of these is covered by a test.

- A path is refused when it is empty, longer than 4096 characters, contains a backslash, starts with `/`, does not end in `.md`, has an empty or `.` segment, uses `..` as a segment, or has no file name (`.md`). A `..` inside a file name, such as `notes..draft.md`, is allowed. Control characters are U+0000–U+001F, U+007F–U+009F, and the line and paragraph separators. The message names the path, and every control character in it is shown as a `\u` escape.
- Paths keep the spelling they were given, including a decomposed letter such as `é`. Planned indexes and links use that spelling, so they name the file on disk. Two paths that are the same after Unicode NFC are still refused. A link in the other spelling still resolves. Comparison does not use a locale. A new index or map is created as mode `0600`. Replacing one keeps its mode, including a private `0600` or a group-readable `0640`.
- `indexName` and `rootMapName` must be different single `.md` file names. Unknown options are refused. `indexThreshold` and `maxLines` are whole numbers from 0 to 1000000. The function does not change the notes it was given.
- Only notes directly in a folder count toward the threshold. Notes in subfolders do not. The root index heading is `Notes`. Any other index heading is that folder's own name.
- A folder index lists a subfolder's notes when that subfolder has no index. The root map does not: it has one line per root note and one line per top-level folder. A folder with an index links to that index. A folder without one links to the folder (`garden/`), which is not a note link. Links are relative to the file that contains the list. Paths sort by UTF-16 code units, so `B.md` comes before `a.md`.
- Front matter opens and closes with a line that is exactly `---`. The first `description:` and `name:` win. Matching quotes are removed. An empty value does not count, and an unclosed block is ordinary text. `## ` is not a `# ` heading.
- A heading or a description is not cut. The first-line fallback is cut to 120 on the last space at or before 120, with no ellipsis. A first word longer than 120 is cut at 120. Whitespace inside an about line becomes one space.
- Link labels escape `\`, `[`, `]`, `(`, `)`, `*`, `_`, `` ` ``, `<`, and `>`. Each path segment percent-encodes every octet that is not an RFC 3986 unreserved character, so spaces, `#`, `?`, and parentheses are encoded. The checker decodes them before lookup.
- A markdown link with a scheme, a `//` prefix, a leading `/`, or only a `#` anchor is ignored. So is a link whose path does not end in `.md`, including images. Reference-style links are ignored. A bad `%` sequence, or a decoded segment that contains `/`, `\`, or a control character, is a broken link. Destinations in `<...>` are accepted, and a destination may contain balanced parentheses, so `[draft](a%20(draft).md)` is a link to `a (draft).md`. A label may contain balanced brackets, so `[the [draft]](draft.md)` is a link too. A label may also wrap onto the next line (`[the\ndraft](draft.md)`). A blank line ends the label. An anchor is not checked; the note only has to exist.
- A `[[name]]`, `[[name#anchor]]`, or `[[name|label]]` link matches a front matter `name:`, a file name without `.md`, or a path without `.md`. The match is case sensitive. Any one note is enough. A `#` starts the anchor, so a file named `plan#1.md` is reached by its encoded markdown link, not by `[[plan#1]]`.
- Fenced code and inline code are not searched. Links in front matter are not searched. A link from a note to itself does not clear an orphan. Links in the whole map file, including the hand-written part, do not clear orphans. Links in a hand-made index do.
- Duplicate comparison trims, lowercases, and treats CRLF as LF. Identical text is one group. The same about line is a second group only when those notes are not already that same text group. A trailing newline does not add a line. The map's limit stays 200 even when `maxLines` changes.
- A generated index may start with a byte-order mark and then the header. The header must be the start of the file. The map marker is the exact string, and the first one wins. The bytes before it are kept. A map with no marker gets a newline, if it needs one, and then the marker.
- A map whose hand-written prefix is not valid UTF-8 keeps those exact bytes on `--write`. They are not replaced with U+FFFD. The section from the marker on is still regenerated. The JSON result is the Unicode reading, so those bytes appear there as the replacement character.
- Health describes the wiki after `writes` and `removes`. A link to an index this run creates is not broken. A link to an index this run removes is broken. A file that changes during `--write` stays as found; health is not recomputed for that race.
- The command skips hidden folders and does not follow a symbolic link. A symbolic link or directory already named `INDEX.md` or `MAP.md` blocks the rebuild before any file is written. It reads a hidden `.md` file in a visible folder. It does not read `.MD`, but on macOS that name still counts in the case check, so an `INDEX.MD` already in a folder blocks the generated index and nothing is written. On macOS it refuses two paths that differ only by simple lower case, because the disk would treat them as one file. On Linux those are two notes. On macOS, a planned `INDEX.md` or `MAP.md` that differs only by case from a note already there is a conflict, and nothing is written. The health list in that result describes the files still on disk, not the rebuild that was not applied.
- `.git` as a file or a folder refuses the directory, and so does the repository root. The message does not repeat the folder's absolute path. The command will not write or delete a path that is not an index or the map, including a path that climbs out with `..`.
- An empty note list still proposes a map that is only the marker. A disk error stops the run; an earlier file in the sorted write list may already be updated, and running again finishes the rest.
