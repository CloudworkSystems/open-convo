## Why

The design note says an Atlas wiki works only if its indexes are always
current, and that every index is generated by one plain-code rebuild that
nobody edits by hand. Steps 1 and 2 of the Steward's run need no model:
they are file lists, links and text comparison. So they can be built now,
as a standalone library, before Atlas or True Convo exists, and the same
code later runs after each kept memory write and in the weekly run.

## What It Does

`buildAtlas(notes, options)` in `packages/atlas-index/`, plain JavaScript,
no dependencies. It takes the wiki as data and returns data. It reads and
writes nothing itself.

### Input

- `notes`: a list of `{ path, text }`. `path` is relative, uses `/`, and
  ends in `.md`. Paths with `..`, a leading `/`, a backslash or a control
  character are refused, naming the path.
- `options` (all optional):
  - `indexName`: the generated index file name, default `INDEX.md`.
  - `rootMapName`: the root map file name, default `MAP.md`.
  - `indexThreshold`: a folder gets an index when it holds more than this
    many notes, default 5 (the design note's "past a handful").
  - `maxLines`: a note longer than this is listed as too long, default 400.
  The root map gets a line count warning above 200 lines (the design
  note's limit).

### The Rebuild (Step 1)

- **What a note is about.** Its first `# ` heading if it has one, else its
  first non-empty line, cut to 120 characters on a word boundary, else the
  file name. Front matter (`---` block at the top) is skipped, and its
  `description:` field wins when present.
- **Folder indexes.** Each folder with more than `indexThreshold` notes
  (not counting its own index) gets an `INDEX.md`: a generated-file header
  line (`<!-- Generated by atlas-index. Do not edit by hand. -->`), the
  folder name as a heading, then one line per note, sorted by path:
  `- [About text](relative/link.md)`. Subfolders are listed after notes,
  each linking to its own index or, if it has none, to its notes.
- **Root map.** `MAP.md` at the root keeps any hand-written part above a
  `<!-- atlas-index:start -->` marker unchanged and regenerates everything
  below it: one line per top-level folder and per root note. A root map
  without the marker gets the marker appended after the hand-written text.
- **Hand-made indexes are never overwritten silently.** An existing
  `INDEX.md` that doesn't start with the generated-file header is reported
  under `conflicts` and left out of `writes`.
- The rebuild returns `writes`: a list of `{ path, text }` for every index
  and the map whose text differs from what's there now, and `unchanged`
  for the ones that already match.
- **Indexes that no longer qualify.** A generated `INDEX.md` (one that
  starts with the generated-file header) in a folder that is now at or
  under `indexThreshold`, or that has no notes left, goes in `removes`, so
  no stale index keeps links to deleted notes. A hand-made `INDEX.md` is
  never in `removes`.

### The Check (Step 2)

Returned as `health`, each entry `{ kind, path, detail }`, sorted by kind
then path:

- `broken-link`: a relative markdown link (`[text](path.md)` or
  `[text](path.md#anchor)`) to a note that doesn't exist. Links with a
  scheme (`https:`, `mailto:`) are ignored and never fetched. A `[[name]]`
  wiki link counts when a note's file name (without `.md`) or its front
  matter `name:` matches; otherwise it is broken.
- `orphan`: a note no other note links to, apart from the generated
  indexes and map. The map and indexes themselves are never orphans.
- `duplicate`: two or more notes whose text is the same after trimming
  whitespace and lowercasing, or whose about lines are the same. Each group
  is listed once, with every path.
- `too-long`: a note over `maxLines` lines, or the map over 200.
- `conflict`: as above.

The check proposes; it never fixes. Only index and map files are ever in
`writes`, and only generated indexes are ever in `removes`.

### Output

`{ writes, removes, unchanged, conflicts, health, counts }`. `counts`
gives notes, folders, indexes written and removed, and each health kind. Lists come out in a fixed
order, so the same input gives byte-identical JSON.

### The Command

`node packages/atlas-index/src/atlas.mjs --dir <folder> [--write] [--json]`

- Reads every `.md` file under `--dir` (not following symbolic links,
  skipping hidden folders), calls `buildAtlas`, and prints a short summary
  (or the JSON).
- **Dry run by default.** Without `--write` it writes nothing. With
  `--write` it writes only the files in `writes`, each one inside `--dir`,
  each by writing a temporary file in the same folder and renaming it, and
  deletes only the files in `removes`, after checking again that each still
  starts with the generated-file header. It never deletes, moves or edits a
  note.
- It refuses a `--dir` that is the repository root or contains a `.git`
  folder, so it can't rewrite this repo's own files by mistake.

## Tests (Must Pass, Run By One Command)

`npm test` in `packages/atlas-index`, Node's built-in test runner, invented
notes only (a small sample wiki in `tests/fixtures/`, for example a
gardening and recipes notebook). At least:

1. A folder with 6 notes gets an index; a folder with 5 doesn't. When a
   note is deleted from the 6-note folder, its generated index is in
   `removes`; a hand-made index in the same case is not.
2. About lines: heading, first line, front matter `description:`, and a
   very long first line cut on a word boundary.
3. The root map keeps its hand-written part above the marker byte for byte;
   a map without the marker gets one.
4. A hand-made `INDEX.md` lands in `conflicts` and not in `writes`.
5. A second run on its own output gives no `writes` (stable).
6. Broken links: a missing note, a missing note with an anchor, a broken
   `[[name]]`, and an `https:` link that is ignored.
7. Orphans and duplicates (same text, and same about line), each group
   listed once.
8. Too-long notes and a map over 200 lines.
9. Refused paths: `..`, a leading `/`, a backslash, a control character.
10. Determinism: shuffled `notes` give byte-identical JSON.
11. The command: a dry run writes nothing (the folder's files and times are
    unchanged), `--write` writes only index and map files inside the
    folder, and a folder with `.git` is refused. These run on a temporary
    copy of the fixture.
12. The library imports no `fs`, network or `child_process` module, and
    the command no network or `child_process` module.

  repo.
